# 질문 우선 화면 (question-first)

사안 하나에 질문 하나. 방법 층위를 순서대로 훑는 대신, 그 사안에서 실제로
갈린(또는 예외 없이 같았던) 지점에서 질문을 하나 뽑고 그것만 깊게 본다.

`tmp/claude-framing-2026-07-26/prototype/report.html`(층위 8개를 한 페이지에
쌓은 화면)의 대안 배치이며, 같은 분석 산출물을 읽는다.

## 만드는 법

```
python prototypes/question-first/build_pages.py [분석산출물경로]
```

경로를 생략하면 상위 디렉터리를 거슬러 올라가며
`tmp/claude-framing-2026-07-26`을 찾는다(gitignore 대상이라 워크트리에는 없다).
결과는 같은 폴더에 `index.html` + `issue-1..5.html`로 나온다. 자체 완결
파일이라 그대로 열면 된다.

## 왜 페이지를 나눴나

- **한 페이지 = 한 사건.** 하루 상위 5개를 탭으로 묶은 것은 산출 단위였고
  소비 단위가 아니다. 파일이 분리되면 링크를 공유하고 다시 열 수 있다.
- **사안마다 화면 모양이 다르다.** 다섯 사안은 발견의 종류가 서로 다르다.
  1·5번은 언론이 수렴한 사안이라 수렴 배너 + 평면 목록, 2·3·4번은 갈린
  사안이라 낱말 기준 나란히 보기.
- **공통과 침묵을 먼저 놓는다.** 기사들이 같게 전한 것과 어디에도 없는 것을
  한 블록에 나란히 둔다. 기존 화면은 전자를 1번, 후자를 5번으로 떼어 놓고
  후자에 경고색을 칠했다.
- **분류가 아니라 문장으로 비교한다.** 5번 사안의 '왜 이렇게 됐나'는 네 기사가
  같은 갈래로 묶이지만 문장은 우발/계획으로 갈린다. 그 갈림을 화면에 그대로
  싣는다.
- **더 읽어도 늘지 않으면 그렇다고 쓴다.** 5번 사안의 추천은 '없음'이다.

## 화면에서 뺀 것

요소 조합 군집, 정책 분류표(Boydstun/Semetko), 낱말 연결망, 형태소 분석은
독자 경로에서 뺐다. 사안당 기사 4~7건에서는 분포를 추정하는 주장이 방어되지
않는다(군집 절단값이 표본 중앙 거리라 갈림이 규칙상 보장되는 등). 연구자용
화면으로 분리하는 것이 서비스 총평 문서의 권고와도 맞는다.

## 기계에서 온 것 / 편집이 쓴 것

| 데이터에서 그대로 | 편집이 쓴 문장 |
| --- | --- |
| 매체·기사 수, 기사 제목·발행 시각·원문 링크 | 중립 제목, 질문 한 줄과 그 아래 설명 |
| 항목별 요약 문장, 출처 처리 방식, 지칭어 | 회색 바탕 문단, '아무도 묻지 않은 것' |
| 인용된 취재원 유형, 개별/구조 서술 여부 | 갈래 이름, 추천 사유 |

각 페이지 맨 아래에 같은 구분을 독자용 문장으로 싣는다. 사람 코더의 이중
코딩은 아직 없으므로(`evals/thresholds.yaml`의 `release_eligible: false`)
화면도 '검증을 마친 결과가 아니라 초안'이라고 밝힌다.
