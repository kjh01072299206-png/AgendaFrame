# AgendaFrame 프레이밍 분석 방법론 v6

## 목적

AgendaFrame은 언론사의 정치 성향이나 진실성을 점수화하지 않는다. 동일 사건을 다룬 기사들이 사건을 어떻게 정의하고, 원인·책임·평가·해법을 어떻게 연결하며, 누구의 목소리와 어떤 맥락을 전면에 두는지 근거에 연결해 비교한다.

## 분석 층위

1. **사건 동일성**
   - 같은 주제가 아니라 같은 행위자·행동·대상·시점의 사건만 직접 비교한다.
   - 발행 시점의 정보 차이를 고려하고 후발 기사에만 알려진 사실을 앞선 기사의 누락으로 처리하지 않는다.
2. **기사별 해석 구조**
   - 문제 정의
   - 원인 해석
   - 책임 귀속
   - 규범적 평가
   - 처방·해법
3. **발언권과 서술 주체**
   - 기자 서술, 직접 인용, 간접 인용, 문서 인용을 구분한다.
   - 취재원의 발언을 매체 자체의 주장으로 자동 변환하지 않는다.
4. **설명의 범위**
   - 일화적 사례와 구조적·제도적 맥락을 구분한다.
   - 통계, 역사, 제도, 인과 메커니즘, 정책 대안, 영향 당사자의 발언 여부를 기록한다.
5. **보조 기술자**
   - 정책 프레임과 갈등·책임·경제적 결과·인간적 흥미·도덕성 같은 일반 프레임은 주된 결론이 아니라 관찰된 표현 방식의 보조 태그로 사용한다.
6. **이슈별 비교**
   - 기사별 분석을 먼저 완료한 뒤 공통 보도, 설명 차이, 취재원 구성, 표본 본문에서 관측되지 않은 맥락을 비교한다.

핵심 분석은 Entman의 문제 정의·원인 해석·평가·처방 구분을 따른다. 반복되는 요소 조합을 이슈 고유의 프레임으로 이해한다는 점은 Matthes와 Kohring의 접근을 따른다. 고정 프레임 분류는 Media Frames Corpus와 Semetko–Valkenburg의 일반 프레임을 보조적으로 활용한다.

- [Entman (1993)](https://doi.org/10.1111/j.1460-2466.1993.tb01304.x)
- [Matthes & Kohring (2008)](https://doi.org/10.1111/j.1460-2466.2008.00384.x)
- [Media Frames Corpus](https://aclanthology.org/P15-2072/)
- [Semetko & Valkenburg (2000)](https://doi.org/10.1111/j.1460-2466.2000.tb02843.x)
- [Computational Framing Analysis Survey](https://aclanthology.org/2022.emnlp-main.633/)

## 한국어 형태소 신호 계층

현재 배포 환경은 `controlled_lexicon_fallback` 모드를 사용한다. 이 모드는 완전한 형태소 분석기가 아니라, Unicode 정규화 뒤 어절을 나누고 자주 쓰이는 조사와 일부 용언 활용을 보수적으로 정규화해 `noun`, `predicate`, `particle`, `number`, `foreign` 범주의 집계 신호를 만드는 경량 규칙형 분석기다. URL·이메일, 보도문 관용어와 분석용 불용어는 핵심어 후보에서 제외한다. `않다·아니다·못하다·없다`는 핵심어 순위에서는 제외하되 별도 `negation_count`로 집계한다. 분석기 버전, 사전 버전과 간이 품사 체계는 결과에 함께 기록한다.

토큰화와 lemma·POS 신호는 프레임의 **후보 생성**에만 사용한다. 특정 단어가 나왔다는 이유만으로 문제 정의·원인·책임·평가·해법 또는 매체의 논조를 확정하지 않는다. 최종 구조화 판정은 다음 조건을 함께 확인한다.

- 같은 문장 안에서 코드북 개념어가 둘 이상 함께 나타나는지, 또는 고정밀 구문이 명시적으로 나타나는지 확인한다.
- 원인 표지, 의무·제안 표현, 평가 술어와 평가 대상처럼 문장 안의 관계를 확인한다.
- `않다`, `아니다`, `못하다`, `없다` 같은 부정 신호를 주변 문맥과 함께 확인한다.
- 직접 인용·간접 인용과 기자 서술을 구분하고, 취재원에게 귀속된 표현을 매체 자체의 평가로 합산하지 않는다.
- 조건을 충족하지 못하면 강제로 분류하지 않고 `not_observed` 또는 `abstained`로 남긴다.

이 경량 분석은 조사·일부 활용의 흔한 형태만 다루므로 미등록어, 복합명사, 불규칙 활용, 띄어쓰기 오류와 문맥적 중의성을 완전하게 해소하지 못한다. 정식 연구·평가 파이프라인에서는 [Kiwi](https://github.com/bab2min/Kiwi) 같은 한국어 형태소 분석기를 Worker 요청 처리 안에 탑재하기보다 오프라인 배치에서 실행하고, 동일한 버전 계약을 따르는 집계 신호만 가져오는 방식을 권장한다. 분석기 교체 시에는 analyzer·dictionary·taxonomy 버전을 함께 올리고 같은 고정 평가셋으로 회귀 검증한다.

## 공개 분석 모듈의 집계 단위

### 프레임 구성

정책 프레임은 기사별 라벨의 **존재 여부(`article_presence`)**를 단위로 집계하는 다중 라벨 보조 지표다. 한 기사에서 같은 라벨이 여러 문장에 나타나도 그 라벨의 기사 수는 한 번만 증가한다. 따라서 긴 기사나 한 표현을 반복한 기사가 막대 비중을 과도하게 키우지 않는다.

- `article_share`는 해당 매체의 분석 기사 중 라벨이 관측된 기사 비율이다.
- `composition_share`는 해당 매체에서 관측된 전체 기사-라벨 할당 중 그 라벨이 차지한 비율이다. 시각화 막대의 구간 크기는 이 값을 사용한다.
- `sentence_count`는 근거가 관측된 문장 수를 설명하기 위한 값이지 가중치나 신뢰도 점수가 아니다.
- 한 기사에 여러 라벨이 동시에 붙을 수 있으므로 라벨별 `article_share`의 합은 100%를 넘을 수 있다.

프레임 구성은 Policy Frames Codebook에서 영감을 받은 기술적 태그이며 완결된 의미론적 프레임, 정치 성향 또는 기사 품질 판정이 아니다.

### 평가 표현과 보도 범위

평가 표현 지수와 보도 범위 지수는 모두 `-1`에서 `+1` 사이의 관측 지수이며 확률이나 보정된 신뢰도가 아니다.

- 기사별 평가 표현 지수는 기자 서술에서 명시적으로 관측된 긍정·부정 정당성 표현에 대해 `(긍정 수 - 부정 수) / (긍정 수 + 부정 수)`로 계산하고, 매체 값은 관측 가능한 기사들의 산술평균으로 계산한다. 취재원 인용에서만 평가가 나타난 기사는 `attributed_only`로 세되 평가 지수에는 넣지 않는다.
- 기사별 보도 범위 지수는 `(주제적 문장 수 - 일화적 문장 수) / (주제적 문장 수 + 일화적 문장 수)`로 계산하고, 매체 값은 관측 가능한 기사들의 산술평균으로 계산한다. 음수는 상대적으로 사건·인물 사례 신호가 많고, 양수는 구조·제도·맥락 신호가 많다는 뜻이다.
- 각 지수의 분모가 0이면 임의로 중앙에 배치하지 않고 `abstained`, `index: null`로 공개한다. 화면의 점 겹침을 피하기 위한 시각적 이동이 있더라도 실제 지수값은 바꾸지 않는다.

평가 지수는 평가 대상별 지지·반대를 확정하지 않으며 언론사의 정치 성향, 우호도 또는 사실성을 뜻하지 않는다.

### 형태소 핵심어 공개 기준

기사별 처리 중에는 순서가 있는 토큰을 메모리에서만 사용한다. 공개 핵심어는 같은 이슈에서 **2개 이상 기사이면서 2개 이상 독립 미디어그룹**에 나타난 lemma·품사 조합만 허용한다. 이 기준을 통과하지 못한 고유·희귀 어휘는 공개 비교에서 제외한다. 매체별 화면에는 허용된 항목 중 내용어 천 개당 빈도가 높은 최대 15개만 표시한다.

이 기준은 희귀 원문 조각의 노출과 단일 매체·단일 기사의 과잉 해석을 줄이기 위한 최소 공개 기준이다. 핵심어 빈도는 해당 표현의 가시성만 나타내며 프레임, 논조, 기사 품질 또는 중요도 점수가 아니다.

## 본문 처리와 저장

- 공개 HTTPS 기사만 요청한다.
- 로그인, 구독, 유료벽, CAPTCHA, 접근 차단 또는 다른 도메인으로의 우회는 시도하지 않는다.
- HTML과 본문은 처리 중 메모리에서만 사용하고 저장하지 않는다.
- 기사별로 본문 해시, 글자 수, 추출 방식, 분석 버전, 구조화된 분석 결과와 순서가 제거된 제한적 형태소 빈도만 저장한다.
- 원문, HTML, 문장, 인용문, 형태소·토큰 순서열은 저장하지 않는다. 저장 프로필은 `raw_body_retained: false`, `raw_tokens_retained: false`를 검증한다.
- 근거는 원문 문장 대신 문단·문장 위치, 비복원 해시, 기사 ID와 독자적으로 작성한 짧은 근거 요약으로 남긴다.
- 화면은 항상 원문 링크를 제공한다.

본문 비저장은 보관·재배포 위험을 낮추는 기술적 통제이지 기사 이용 허락이나 법적 면책을 의미하지 않는다.

## 근거와 유보 규칙

- 근거 위치가 없는 분석값은 공개하지 않는다.
- 제목만 확보한 기사는 원인·책임·평가·해법을 분석하지 않는다.
- 직접적인 근거가 없으면 `not_observed` 또는 `abstained`로 기록한다.
- 인용된 취재원의 견해와 기사 자체의 서술을 분리한다.
- 기사 형식과 사건 군집이 비교에 적합하지 않으면 비교 전체를 유보한다.
- “의도적으로 누락”, “편향”, “거짓”처럼 의도나 진실성을 판정하는 표현을 생성하지 않는다.
- 비교 공백은 “분석 대상 본문에서는 확인되지 않았다”고 표현한다.
- 검증 데이터가 준비되기 전에는 모델이나 규칙이 생성한 임의의 신뢰도 숫자를 제공하지 않는다.

## 공개 상태

- `automatic_draft`: 자동 구조화 결과이며 사람 검토 전
- `partial`: 일부 분석 축만 근거로 확인됨
- `human_reviewed`: 코드북 기준의 사람 검토 완료
- `withheld`: 본문, 사건 동일성 또는 근거가 부족해 공개 유보

현재 자동 분석은 연구 코드북을 구현한 추출형 초안이다. 학술적으로 검증된 사람 코딩 결과나 완전한 의미론 모델 결과로 표시하지 않는다.

## 평가 게이트

출시 적격성은 기사 수가 아니라 선택적 위험으로 판단한다.

- 본문 파싱 정밀도
- 근거 위치 정확도와 근거 함의 정밀도
- 근거 없는 분석률
- 화자 귀속 F1
- 분석 축별 macro-F1
- 서로 다른 입력 시점과 반복 실행의 일관성
- 분석 유보의 정밀도·재현율
- 사람 코더 간 Krippendorff's alpha

사람 골드셋과 평가 결과가 없는 자동 결과는 계속 `검토 전`으로 표시한다.
