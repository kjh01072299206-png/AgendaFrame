## 유스케이스 단위 분할 기준

- 유스케이스는 사용자가 얻는 주요 목표 단위로 나눈다.
- 버튼 클릭이나 내부 계산처럼 독립 목표가 약한 기능은 관련 유스케이스의 정상 흐름 또는 대안 흐름에 포함한다.
- 백엔드 자동 처리라도 사용자 화면의 분석 결과를 생성하는 핵심 기능이면 하나의 시스템 유스케이스로 둔다.

**UC-01**

유스케이스명 : UC-01 분석 조건 설정 및 의제 조회

액터 : 사용자

목표 : 사용자가 정책 분야, 기간, 언론사, 키워드 조건에 맞는 오늘의 주요 의제를 순위로 확인한다.

사전 조건 : 기사 수집, 이슈 클러스터링, 의제 점수 계산이 완료되어 조회 가능한 의제 데이터가 존재해야 함.

정상 흐름

1. 사용자는 AgendaFrame 대시보드에 접속한다.
2. 시스템은 기본 조회 조건을 오늘 날짜, 전체 정책 분야, 전체 언론사로 설정하여 표시한다.
3. 사용자는 필요에 따라 정책 분야, 기간, 언론사, 키워드 조건을 변경한다.
4. 사용자는 [조회] 버튼을 누른다.
5. 시스템은 입력된 조회 조건의 형식과 필수값을 검증한다.
6. 시스템은 조건에 맞는 의제 데이터를 조회한다.
7. 시스템은 의제명, 정책 분야, 중요도 점수, 관련 언론사 수, 관련 기사 수를 중요도 순으로 출력한다.
8. 사용자는 관심 있는 의제를 선택한다.

대안 흐름

A1 : 조회 조건 오류

1. 정상 흐름 5단계에서 기간 형식이 맞지 않거나 검색어가 허용 길이를 초과하면 시작한다.
2. 시스템은 잘못 입력된 항목 옆에 오류 메시지를 표시한다.
3. 사용자가 조건을 수정하면 정상 흐름 4단계로 돌아간다.

A2 : 조회 조건에 해당하는 의제 없음

1. 정상 흐름 6단계에서 조건에 맞는 의제가 없으면 시작한다.
2. 시스템은 "해당 조건에 맞는 분석 의제가 없습니다. 조건을 변경해 주세요."라는 안내를 표시한다.
3. 사용자는 정상 흐름 3단계로 돌아가 조건을 다시 설정한다.

A3 : 조건 초기화

1. 정상 흐름 3~4단계 진행 중 사용자가 [초기화] 버튼을 누르면 시작한다.
2. 시스템은 정책 분야, 기간, 언론사, 키워드 조건을 기본값으로 복원한다.
3. 사용자는 정상 흐름 3단계 또는 4단계로 돌아가 흐름을 이어서 진행한다.

종료 조건 : 조건에 맞는 의제 목록이 화면에 출력되고 사용자가 특정 의제를 선택할 수 있다.

**UC-02**

유스케이스명 : UC-02 이슈 상세 조회

액터 : 사용자

목표 : 사용자가 특정 의제의 요약 설명, 의제 점수 근거, 관련 기사 목록과 원문 링크를 확인한다.

사전 조건 : [UC-01] 분석 조건 설정 및 의제 조회가 완료되어 사용자가 특정 의제를 선택할 수 있어야 함.

정상 흐름

1. 사용자는 의제 목록에서 확인하고 싶은 이슈를 클릭한다.
2. 시스템은 선택된 이슈 ID를 기준으로 상세 데이터를 조회한다.
3. 시스템은 이슈 제목, 요약 설명, 정책 분야, 의제 중요도 점수와 주요 산출 근거를 출력한다.
4. 시스템은 관련 기사 목록을 제목, 언론사명, 섹션, 수집 시각, 원문 링크와 함께 출력한다.
5. 사용자는 기사 목록을 최신순, 언론사순, 의제 점수 기여도순 중 하나로 정렬한다.
6. 시스템은 선택된 정렬 기준에 맞춰 기사 목록을 다시 출력한다.
7. 사용자가 원문 링크를 클릭하면 시스템은 해당 기사 페이지를 새 탭 또는 새 창으로 연다.

대안 흐름

A1 : 이슈 상세 데이터 없음

1. 정상 흐름 2단계에서 선택된 이슈 ID에 해당하는 상세 데이터가 없으면 시작한다.
2. 시스템은 "선택한 이슈의 상세 데이터를 찾을 수 없습니다."라는 안내를 표시한다.
3. 사용자가 확인하면 [UC-01]의 의제 목록 화면으로 돌아간다.

A2 : 관련 기사 목록 로딩 실패

1. 정상 흐름 4단계에서 기사 목록 데이터를 불러오지 못하면 시작한다.
2. 시스템은 이슈 요약 영역은 유지하고 기사 목록 영역에 오류 안내와 [재시도] 버튼을 표시한다.
3. 사용자가 [재시도] 버튼을 클릭하면 정상 흐름 4단계로 돌아간다.

A3 : 원문 기사 접근 불가

1. 정상 흐름 7단계에서 원문 URL이 없거나 기사 페이지 접근에 실패하면 시작한다.
2. 시스템은 해당 기사 항목에 "원문 기사로 이동할 수 없습니다."라는 상태를 표시한다.
3. 사용자는 기존 이슈 상세 화면 상태를 유지한다.

종료 조건 : 이슈 상세 정보와 관련 기사 목록이 화면에 출력된다.

**UC-03**

유스케이스명 : UC-03 언론사별 보도 비교

액터 : 사용자

목표 : 사용자가 같은 이슈에 대해 언론사별 보도 건수, 제목 표현, 홈페이지 배치 차이를 비교한다.

사전 조건 : [UC-02] 이슈 상세 조회가 완료되어 선택된 이슈에 관련 기사 데이터가 존재해야 함.

정상 흐름

1. 사용자는 이슈 상세 화면에서 [언론사별 보도 비교] 영역을 확인한다.
2. 시스템은 선택된 이슈에 포함된 기사를 언론사별로 집계한다.
3. 시스템은 언론사별 기사 수, 기사 제목, 섹션, 홈페이지 배치 위치를 계산한다.
4. 시스템은 언론사별 보도 건수와 배치 위치를 표 또는 그래프로 출력한다.
5. 시스템은 같은 이슈를 다룬 언론사별 제목을 나란히 출력한다.
6. 시스템은 제목에서 반복적으로 등장하거나 강조된 핵심 단어를 표시한다.

대안 흐름

A1 : 특정 언론사 보도 없음

1. 정상 흐름 2단계에서 분석 대상 언론사 중 특정 언론사의 관련 기사가 없으면 시작한다.
2. 시스템은 해당 언론사 영역에 "해당 언론사 보도 없음" 상태를 표시한다.
3. 시스템은 나머지 언론사의 비교 결과는 정상적으로 출력한다.

A2 : 비교 가능한 언론사 수 부족

1. 정상 흐름 2단계에서 선택된 이슈를 보도한 언론사가 1개뿐이면 시작한다.
2. 시스템은 "비교 가능한 다른 언론사 보도가 부족합니다."라는 안내 문구를 출력한다.
3. 시스템은 존재하는 기사 목록과 해당 언론사의 배치 정보만 표시한다.

종료 조건 : 언론사별 보도 건수, 제목, 배치 위치 비교 결과가 화면에 출력된다.

**UC-04**

유스케이스명 : UC-04 관점/프레임 비교

액터 : 사용자

목표 : 사용자가 같은 이슈에 대해 언론사별로 어떤 관점과 프레임이 강조되었는지 확인한다.

사전 조건 : [UC-07] 기사 자동 수집 및 분석이 완료되어 프레임 분석 결과가 저장되어 있어야 함.

정상 흐름

1. 사용자는 이슈 상세 화면에서 [관점/프레임 비교] 영역을 확인한다.
2. 시스템은 선택된 이슈의 기사별 프레임 분석 결과를 조회한다.
3. 시스템은 문제정의·원인·책임·평가·해법과 취재원 구조를 언론사별로 계산한다. (설계 당시에는 갈등·책임·경제·법제도·정책효과·시민영향 6종 태그였고, 이 6종은 레거시 보조 태그로 남아 있다.)
4. 시스템은 언론사별 프레임 비중을 그래프 또는 표로 출력한다.
5. 사용자는 확인하고 싶은 프레임 항목을 선택한다.
6. 시스템은 해당 프레임으로 분류된 기사 제목 표현 또는 근거 문장을 출력한다.

대안 흐름

A1 : 프레임 분석 결과 없음

1. 정상 흐름 2단계에서 선택된 이슈의 프레임 분석 결과가 없으면 시작한다.
2. 시스템은 "아직 프레임 분석 결과가 없습니다."라는 안내 문구를 표시한다.
3. 사용자는 이슈 상세 화면의 다른 정보만 확인한다.

A2 : AI 분석 신뢰도 낮음

1. 정상 흐름 3단계에서 특정 기사 또는 이슈의 분석 신뢰도가 기준값보다 낮으면 시작한다.
2. 시스템은 해당 결과에 "검토 필요" 상태를 표시한다.
3. 시스템은 그래프와 근거 문장은 출력하되 사용자가 신뢰도 상태를 함께 확인할 수 있게 한다.

종료 조건 : 프레임 비중과 선택된 프레임의 근거 표현이 화면에 출력된다.

**UC-05**

유스케이스명 : UC-05 AI 리포트 조회

액터 : 사용자, 외부 AI 서비스(Vertex AI Gemini)

목표 : 사용자가 특정 이슈에 대한 주요 관점, 부족한 관점, 치우침 가능성을 AI 요약 리포트로 확인한다.

사전 조건 : [UC-02] 이슈 상세 조회가 완료되어 있고, 관련 기사 목록과 프레임 분석 결과가 존재해야 함.

정상 흐름

1. 사용자는 이슈 상세 화면에서 [AI 리포트] 영역을 연다.
2. 시스템은 선택된 이슈에 대해 이미 생성된 AI 리포트가 있는지 확인한다.
3. 저장된 리포트가 있으면 시스템은 해당 리포트 데이터를 조회한다.
4. 저장된 리포트가 없으면 시스템은 기사 메타데이터, 언론사별 보도 비교 수치, 프레임 분석 수치를 프롬프트 템플릿에 결합한다.
5. 시스템은 완성된 프롬프트를 외부 AI 서비스에 전송한다.
6. 외부 AI 서비스는 주요 관점 요약, 상대적으로 부족한 관점, 치우침 가능성, 참고 원문 링크를 포함한 텍스트를 생성한다.
7. 시스템은 수신한 리포트를 저장하고 [AI 리포트] 영역에 출력한다.

대안 흐름

A1 : 외부 AI 서비스 호출 실패 및 타임아웃

1. 정상 흐름 5단계에서 외부 AI 서비스의 서버 장애, 인증 오류, 응답 타임아웃이 발생하면 시작한다.
2. 시스템은 기존 이슈 상세 정보, 언론사별 비교, 프레임 비교 영역은 유지한다.
3. 시스템은 [AI 리포트] 영역에 "AI 리포트를 생성하는 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요."라는 안내와 [재시도] 버튼을 출력한다.
4. 사용자가 [재시도] 버튼을 클릭하면 정상 흐름 5단계로 돌아간다.

A2 : 리포트 생성에 필요한 기사 수 부족

1. 정상 흐름 4단계에서 리포트 생성에 필요한 최소 기사 수 또는 언론사 수가 부족하면 시작한다.
2. 시스템은 "분석 가능한 기사 수가 부족해 AI 리포트 생성을 보류했습니다."라는 안내를 출력한다.
3. 시스템은 사용자가 확인 가능한 기사 목록과 보도 비교 정보만 유지한다.

종료 조건 : AI 리포트가 화면에 출력되거나 생성 보류/실패 상태가 안내된다.

**UC-06**

유스케이스명 : UC-06 결과 요약 PDF 내보내기

액터 : 사용자

목표 : 사용자가 현재 조회 중인 이슈 분석 결과를 PDF 파일로 저장한다.

사전 조건 : [UC-02] 이슈 상세 조회가 완료되어 화면에 이슈 요약, 관련 기사, 비교 결과 중 하나 이상이 출력되어 있어야 함.

정상 흐름

1. 사용자는 이슈 상세 화면에서 [PDF 내보내기] 또는 다운로드 아이콘을 클릭한다.
2. 시스템은 현재 화면의 이슈 제목, 요약, 의제 점수, 언론사별 보도 비교, 프레임 비교, AI 리포트 데이터를 가져온다.
3. 시스템은 가져온 데이터를 PDF 템플릿에 결합한다.
4. 시스템은 PDF 파일을 생성한다.
5. 시스템은 브라우저 다운로드 또는 디바이스 파일 저장 창을 통해 PDF 저장을 진행한다.
6. 사용자는 저장 경로와 파일명을 확인한다.
7. 시스템은 PDF 파일을 디바이스에 저장한다.

대안 흐름

A1 : AI 리포트가 아직 생성되지 않음

1. 정상 흐름 2단계에서 AI 리포트 데이터가 없으면 시작한다.
2. 시스템은 AI 리포트 영역을 제외한 나머지 분석 결과로 PDF를 생성할지 사용자에게 확인한다.
3. 사용자가 확인하면 정상 흐름 3단계로 돌아간다.

A2 : PDF 생성 실패

1. 정상 흐름 4단계에서 PDF 생성 또는 파일 변환 오류가 발생하면 시작한다.
2. 시스템은 "PDF 파일을 생성하는 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요."라는 안내와 [재시도] 버튼을 출력한다.
3. 사용자가 [재시도] 버튼을 클릭하면 정상 흐름 2단계로 돌아간다.

A3 : 사용자가 저장 취소

1. 정상 흐름 5단계에서 사용자가 파일 저장 창을 닫거나 다운로드를 취소하면 시작한다.
2. 시스템은 PDF를 저장하지 않고 기존 이슈 상세 화면을 유지한다.

종료 조건 : PDF 파일이 사용자의 디바이스에 저장되거나 저장 취소/실패 상태가 안내된다.

**UC-07**

유스케이스명 : UC-07 기사 자동 수집 및 분석

액터 : 시스템, 언론사 홈페이지, 외부 AI 서비스(Vertex AI Embeddings, Vertex AI Gemini)

목표 : 시스템이 정해진 주기마다 기사 메타데이터를 수집하고, 유사 기사를 이슈로 묶어 의제 점수와 프레임 분석 결과를 생성한다.

사전 조건 : 분석 대상 언론사, 수집 주기, 정책 분야, 프레임 기준이 등록되어 있어야 함.

정상 흐름

1. 시스템 스케줄러는 정해진 시간에 기사 수집 작업을 실행한다.
2. 시스템은 등록된 언론사 목록과 수집 규칙을 조회한다.
3. 시스템은 각 언론사 홈페이지에서 기사 제목, URL, 언론사명, 섹션, 홈페이지 배치 위치, 수집 시각을 추출한다.
4. 시스템은 중복 기사를 제외하고 신규 기사 메타데이터를 저장한다.
5. 시스템은 기사 제목과 요약 가능 정보를 기반으로 임베딩 벡터를 생성한다.
6. 시스템은 임베딩 유사도를 기준으로 유사 기사를 하나의 이슈로 묶는다.
7. 시스템은 각 이슈의 대표 제목과 요약 설명을 생성한다.
8. 시스템은 언론사 수, 기사 수, 홈페이지 배치 위치, 반복 노출 정도를 반영해 의제 중요도 점수를 계산한다.
9. 시스템은 외부 AI 서비스에 기사별 프레임 분석을 요청한다.
10. 시스템은 이슈 클러스터, 의제 점수, 프레임 분석 결과, 수집 로그를 저장한다.
11. 시스템은 저장된 결과를 대시보드에서 조회 가능한 상태로 만든다.

대안 흐름

A1 : 특정 언론사 수집 실패

1. 정상 흐름 3단계에서 특정 언론사 홈페이지 접속 또는 데이터 추출에 실패하면 시작한다.
2. 시스템은 해당 언론사의 실패 사유와 시각을 수집 로그에 저장한다.
3. 시스템은 나머지 언론사의 수집 작업을 계속 진행한다.

A2 : 중복 기사 발견

1. 정상 흐름 4단계에서 이미 저장된 기사로 확인되면 시작한다.
2. 시스템은 해당 기사를 신규 저장 대상에서 제외한다.
3. 시스템은 중복 제외 건수를 수집 로그에 기록하고 정상 흐름을 이어서 진행한다.

A3 : 임베딩 또는 프레임 분석 실패

1. 정상 흐름 5단계 또는 9단계에서 외부 AI 서비스 호출 실패, 요청 한도 초과, 응답 오류가 발생하면 시작한다.
2. 시스템은 해당 기사 또는 이슈의 분석 상태를 "재시도 필요" 또는 "분석 실패"로 저장한다.
3. 시스템은 성공한 기사와 이슈에 대해서는 나머지 분석 결과를 저장한다.

A4 : 배치 위치 데이터 누락

1. 정상 흐름 8단계에서 기사 배치 위치 값이 누락되었으면 시작한다.
2. 시스템은 기본 배치 가중치를 적용하고 해당 기사에 "배치 위치 검토 필요" 상태를 표시한다.
3. 시스템은 나머지 점수 요소를 반영해 의제 점수를 계산한다.

종료 조건 : 기사 메타데이터, 이슈 클러스터, 의제 중요도 점수, 프레임 분석 결과가 저장된다.
