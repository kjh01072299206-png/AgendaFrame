# 사용자 흐름 관점 개편 피드백 (2026-08-05)

조사 근거: 라우트 22개·워커 라우트 전수·D1 스키마·컴포넌트 실측. 모든 주장에 `파일:줄`.
이 문서는 진단과 제안만 담는다. 코드는 고치지 않았다.

---

## 0. 먼저: 이 사이트는 지금 "누가 어떻게 쓴다"고 전제하고 있는가

코드가 전제하는 사용자는 **한 번 와서, 한 화면을 읽고, 아무것도 남기지 않고 떠나는 사람**이다.
근거:

- 계정이 없다. 로그인·회원가입·로그아웃 라우트 0개. `site/app/chatgpt-auth.ts`(87줄)는 완성돼 있으나
  **import하는 파일이 0개**이고 `/signin-with-chatgpt` 라우트도 없다.
- 사용자가 남긴 것을 사용자에게 되돌려주는 화면이 없다. 자가점검 결과는 localStorage
  (`reader-type.tsx:217-218`)에, 커뮤니티 글은 글 단위 `display_name`(`db/schema.ts` `communityComments`)에
  들어가고, "내 결과"·"내 글" URL이 없다.
- 표시 이름이 새로고침에 사라진다. `displayName`은 `useState`뿐이고 초기값 `"익명 독자"`
  (`community-feed.tsx:149`). 저장 호출이 없다.
- 온보딩·최초 방문 안내가 0건(검색어 `onboarding`, `첫 방문`, `둘러보기`).
- 설정 화면이 없다. 사용자가 바꿀 수 있는 값 4개가 서로 다른 4곳에 흩어져 있다(§3).

그런데 서비스가 하려는 것은 그 반대다. 자가점검으로 **읽기 유형**을 만들고, 그 유형을
커뮤니티 배지로 쓰고(`community-feed.tsx:90-94`), 의제별로 의견을 쌓는다. 이것은
**돌아오는 사용자**를 전제하는 기능이다. 기능은 재방문을 요구하는데 구조는 재방문을
지원하지 않는다. 이 어긋남이 아래 문제들의 공통 원인이다.

## 2. 정체성·계정 (로그인/회원가입) — 무엇을 어디까지

사용자 지적대로 자가점검·커뮤니티를 하려면 신원이 필요하다. 다만 **필요한 것은 "계정"이
아니라 "이어짐"**이다. 지금 없는 것을 정확히 나열하면:

1. 기기 간 이어짐 (localStorage UUID + `af_session` 쿠키 모두 기기 로컬)
2. "내 글" 식별 → 수정·삭제 불가
3. 표시 이름의 소유·중복 방지
4. 내 활동 모아 보기 화면
5. 데이터 삭제 요청 경로

이 5개 중 **1·2·3은 복구 코드(1단계)로 해결되고, 4는 화면 하나, 5는 엔드포인트 하나**다.
소셜 로그인 없이 5개를 다 덮을 수 있다. 소셜 로그인은 알림·팔로우 같은 기능이 생길 때
도입하면 된다.

주의(코드 근거): 쿠키가 헤더보다 우선하므로(`community.mjs:108-110`) localStorage를 지워도
신원이 유지되고, 쿠키만 지우면 다른 해시가 된다. 사용자에게 "로그아웃"처럼 보이는 동작이
없는데 신원은 1년(`Max-Age=31536000`) 유지된다. **설정에 "이 기기에서 신원 초기화"가 필요하다.**

## 3. 설정 페이지 — 지금 흩어진 값과 모을 근거

사용자가 바꿀 수 있는 값의 현재 위치(실측):

| 값 | 지금 어디에 | 저장 | 문제 |
|---|---|---|---|
| 테마 | 상단바 버튼 (`shell-chrome.tsx:174-177`) | `localStorage["afs-theme"]` | 2상태 토글만. "시스템 따르기"로 되돌릴 방법 없음 |
| 표시 이름 | 커뮤니티 **글쓰기 폼 안** (`community-feed.tsx:284`) | React state | 새로고침 시 초기화. 글 쓸 때마다 다시 입력 |
| 읽기 유형 | `/tools/self-check` 문항 | `localStorage["afs-reader-type"]` | 기기 종속. 초기화 버튼 없음 |
| 현재 의제 | 상단바 select + ask 폼 + 커뮤니티 폼 (**3곳 각각 별도 state**) | 없음 | 세 곳이 서로 동기화되지 않음 |
| 피드 정렬 | 커뮤니티 버튼 | React state | 유지 안 됨 |
| 글씨 크기 | **없음** | — | 본문 밀도가 높은 서비스인데 조절 수단 없음 |
| 알림 | **없음** | — | — |

설정 페이지(`/settings`)에 모아야 하는 이유는 "정리"가 아니라 **각 값이 화면 밖에서도
유지돼야 하기 때문**이다. 표시 이름이 글쓰기 폼 안에 있는 한 그것은 "이 글의 서명"이지
"내 이름"이 될 수 없다.

제안 구성:

```
/settings
├ 표시 방식      테마(시스템/밝게/어둡게) · 글씨 크기(3단) · 애니메이션 줄이기
├ 나             표시 이름 · 읽기 유형(결과 요약 + 다시 하기 + 지우기)
├ 다른 기기      복구 코드 발급/입력 · 이 기기에서 신원 초기화
├ 읽기 기록      본 의제·층위 진행률 · 기록 지우기
└ 데이터         무엇을 저장하는지 목록 · 내 데이터 삭제 요청
```

"데이터" 섹션은 선택이 아니라 필수다. 지금 사이트는 익명 해시·자가점검 응답·글을 저장하면서
**사용자에게 그 목록을 보여주는 화면이 없다.**

제안:
- 모바일: 가로 스크롤 링크 줄을 **하단 탭 4개(홈·의제·도구·설정)** + 의제 내 탭으로 바꾼다.
  9개를 평평하게 늘어놓지 않는다.
- `<header role="banner">`/`<footer role="contentinfo">` 도입, skip link는 `:focus`에도 반응하게
  (지금 `:focus-visible`만 — `app-round2.css:242`).
- select 변경 즉시 이동(버튼 제거).
- 레거시 3화면(`/dashboard`, `/top5-2026-07-26`, `/admin`)은 셸로 흡수하거나 `noindex` +
  배포 제외. 프로토타입 HTML은 `.vercelignore`로 배포에서 뺀다.

## 5. 화면별 세부 개선점

### 홈
- KPI 4개가 무엇을 뜻하는지 숫자 옆에서 즉시 안 읽힌다. 각 숫자에 "이게 크면/작으면 무슨
  뜻" 한 줄이 필요하다.
- 층위별 갈림 미터의 `ghost` 점(취재원 포함 시 갈림)은 개념이 정교하지만 범례가 약하다.
  "속이 빈 점 = 매체 자체 서술이 아니라 취재원 발언까지 세면 갈리는 경우"를 점 옆에 붙인다.
- 빈 상태가 문장 분기로만 처리된다(`:84`, `:301`). 전용 빈 상태 표현(연한 상자 + 이유)이 없어
  "데이터가 없는 것"과 "그렇게 관측된 것"이 구분되지 않는다.

### 이슈 탐색
- 히트맵 2개가 연달아 나오는데 축이 다르다(의제×층위, 의제×매체). 두 히트맵 사이에
  "무엇이 다른 질문인지" 한 줄이 필요하다.
- 카드에서 4화면으로 나가는 링크가 나란히 있어 우선순위가 없다. "먼저 여기부터"를 표시한다.

### 사안 개요
- 기사 표가 화면 맨 아래에 길게 놓인다. 매체별로 접어 두고, 기본은 "이 의제의 6개 매체"
  요약만 보이게.

### 언론사 비교
- 나가는 링크 0개. 스펙트럼을 본 다음의 자연스러운 행동은 "그 매체의 문장 보기"인데
  프레이밍 분석으로 가는 링크가 없다.
- 히트맵(매체×취재원역할)에 "이 표에서 무엇을 읽어야 하는가"가 없다.

### 프레이밍 분석
- 결론 배너 → 층위 레일 → 층위별 항목 구조는 좋다. 다만 **의역 문장이 근거의 전부**로
  보인다. "원문 문장을 그대로 옮기지 않는다"는 원칙은 방법론 화면에만 있고, 이 화면
  각 항목 옆에는 없다. 항목마다 "의역" 표시가 필요하다.
- `발췌본 문장 3·5·4 · 근거 3문장` 표기는 정확하지만 처음 보면 해독이 안 된다.

### 리포트
- 나가는 링크 0개. 리포트는 마지막 화면이므로 여기서 커뮤니티·자가점검으로 보내야 한다.

### AI 대화
- "답변 보류"가 오류처럼 보인다. 보류는 설계 의도(근거 없으면 답하지 않음)인데 화면에서
  실패와 구분이 약하다. 보류를 **자랑거리로** 표시해야 한다("근거가 없어 답하지 않았습니다"를
  강조 색으로).
- 추천 질문 4개가 고정이다. 의제를 바꾸면 그 의제에서 답할 수 있는 질문으로 바뀌어야 한다.

### 자가점검
- 12문항이 한 화면에 전부 나온다. 진행률·한 문항씩 넘기기가 없다. 완주율에 직접 영향.
- 결과 카드 다음 행동이 커뮤니티 링크 하나(`reader-type.tsx:338`). 유형별로 "당신이 놓치기
  쉬운 층위 → 그 층위 화면으로" 보내는 것이 이 서비스의 핵심 가치와 연결된다.
- 16유형 표가 결과 전에 노출된다(미완성 시). 결과를 보기 전에 정답표를 보여주는 셈이다.

### 커뮤니티
- 첫 렌더 `mode:"checking"`에 시각 표시가 없어(`community-feed.tsx:145`) 빈 화면 구간이 생긴다.
- 정렬·페이지네이션이 전역 경로에서만 동작한다. 폴백 사용 시 `setCursor(null)`(`:190`)로
  "더 불러오기"가 사라진다 — 사용자에게는 기능이 있다가 없어지는 것으로 보인다.
- 글이 의제에 묶이는데 **의제 화면에 커뮤니티 섹션이 없다.** 프레이밍 분석을 보고 바로
  말하고 싶은 곳에 입력창이 없다.
