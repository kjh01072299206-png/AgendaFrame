# 시안 → 실배포 이관 명세 (2026-08-05)

시안: <https://agendaframe-capstone.vercel.app/v2/> (`site/public/v2/index.html`, noindex)
근거 문서: [사용자 흐름](2026-08-05-user-flow.md) · [프레이밍 방법론](2026-08-05-framing-method.md)

시안은 **가상 예시 내용으로 만든 설계 사양서**다. 아래는 시안이 결정한 것을 실배포
(`site/app/**`)에 옮기는 순서다. 각 항목에 시안의 근거와 실배포에서 손댈 파일을 적었다.

## 0. 시안이 잡아낸 것 중 실배포에도 있는 결함

시안을 만들면서 발견한 문제 중 **실배포에도 그대로 있는 것**이다. 시안 없이는 보이지 않았다.

| # | 결함 | 실배포 위치 | 왜 문제인가 |
|---|---|---|---|
| 1 | 홈 집계와 의제×층위 표가 어긋날 수 있다 | `app/(shell)/page.tsx` ↔ `app/(shell)/issues/page.tsx` | 두 화면이 같은 데이터를 각자 계산한다. 계약 테스트가 없다 |
| 2 | 쟁점 축이 범주형 라벨에 연속 좌표를 만든다 | `lib/initial-five/derive.ts` `spectrum()`, `app/charts.tsx` Spectrum | 좌표 계산 규칙이 화면에 없고, 형태가 AllSides 와 같다 |
| 3 | 결측(기자 서술 0건)이 축 가운데에 놓인다 | 같은 곳 (`nested:false` 마크) | 그 매체가 "중도"로 읽힌다 |
| 4 | 일치율 표에 데이터에 없는 차원이 있다 | `data/coder-agreement-2026-07-26.json` `method.dimensions` 6개 vs 산출 5개 | 없는 차원의 값이 평균에 들어간다 |
| 5 | "재현 안정성"이라는 용어 | `app/(shell)/tools/method/page.tsx` | Krippendorff 세 수준 중 가장 약한 것을 표준처럼 부른다 |
| 6 | 규범적 평가 0건을 관행으로 단정 | 홈·방법론 문구 | 방법의 산물일 가능성 세 개를 배제하지 못했다 |
| 7 | 출처 배지가 툴팁뿐 | `app/app-round2.css` `.afs-prov` | 휴대폰에서 볼 방법이 없다 |
| 8 | 표시 이름이 새로고침에 사라진다 | `tools/community/community-feed.tsx:149` | `useState` 뿐이고 저장 호출이 없다 |
| 9 | 의제 4화면에 페이지 title 이 없다 | `app/(shell)/issues/[issueId]/**` | 공유가 유통 경로인데 공유하면 무엇인지 알 수 없다 |
| 10 | 커스텀 404 가 없다 | `app/**/not-found.tsx` 없음 | 없는 의제 URL 은 사이드바 없는 영문 화면 |

## 1. 곧바로 옮길 것 (데이터 재생산 불필요, 화면 수정만)

### 1-1. 출처 배지 3종 + 범례 고정 + 탭 가능
시안: `.prov` 3종(`p-code` / `p-rule` / `p-derive`) + 분석 화면 상단 `.legend` + 탭하면 팝오버.
- 실배포에 이미 `.afs-prov`가 있으나 `title` 툴팁이다 → `<button>` + 다이얼로그로.
- **이유**: 화면의 정책 프레임·일화적/주제적·의제 군집은 이중코딩 산출이 아니다. 배지 없이 섞이면
  일치율 89%가 정규식 산출에도 적용되는 것처럼 읽힌다.
- 손댈 곳: `app/(shell)/layout.tsx`(범례), `app/app-round2.css`, 각 지표 렌더 지점.

### 1-2. 파이프라인 의존 도식
시안: `규칙 엔진(군집) → 이중코딩(층위) → 파생(갈림)` + "앞 단계의 품질이 뒤 단계의 상한".
- **이유**: 배지를 병렬로 놓으면 층위 비교가 규칙 군집 위에 얹혀 있다는 사실이 숨는다.
  rank1·rank4 는 `clusterQuality: review_required`인데 화면에 없다.
- 손댈 곳: `tools/method/page.tsx`, 의제 헤더에 군집 품질 칩.

### 1-3. 신뢰도 표기 정정
- `모델 재현 안정성` → **`프롬프트 변형 간 원 일치율 (p_o)`**, Krippendorff 세 수준 명시.
- `미측정`(사람 코더 간 신뢰도) 카드를 **0.89보다 먼저** 놓는다.
- 층위별 표에 `최빈 계열 비율` 열 추가 → 원인 해석 1.00 이 "변별 없음"임을 독자가 판단할 수 있게.
- `취재원 가시성` 행 삭제, "6층위" → "5층위".
- 손댈 곳: `tools/method/page.tsx`, `data/coder-agreement-*.json`(method 블록 문구).

### 1-4. 쟁점 축을 이산 배치로
시안: 2칸(관측된 두 계열) + 점선 아래 `축 밖`(결측) + 배치 규칙 명시.
- 좌표를 유지하려면 규칙을 화면에 쓴다: `좌표 = 해당 계열 근거 항목 / 그 매체의 이 층위 전체 항목`.
- 손댈 곳: `derive.ts` `spectrum()`(marks 에 좌표 대신 slot), `app/charts.tsx` Spectrum.

### 1-5. 규범적 평가 0건을 "보류"로
시안 문구를 그대로 옮긴다 — 배제하지 못한 설명 3개(① 계열 8종이 명시적 찬반을 요구 ② "이념·의도를
추론하지 말라" 지침 ③ 표본에 사설 없음) + 사설 10건 대조 계획.
- 손댈 곳: 홈 발견 카드, `framing/page.tsx` L4 카드, 일치율 표의 해당 행 경고.

### 1-6. 민감도 토글이 본문까지 바꾸게
시안: `data-basis` 속성에 두 기준의 문장을 담고 토글이 갱신 + `갈린 층위 2개 → 4개` 요약.
- 실배포는 기준 전환 UI 자체가 없다(홈 미터의 ghost 점으로만 암시).
- **이유**: 결론이 채점 규칙에 얼마나 의존하는지 독자가 직접 확인하는 것 = 화면에 올린 민감도 분석.

### 1-7. 층위별 구성 막대 (기자 문장 | 인용)
시안: 문제 정의 28|9 → 원인 16|23 → 책임 5|36 → 평가 0|33 → 해법 6|33, 공유축(최대 41).
- **이유**: "0건"이 고립된 숫자가 아니라 단조 추세의 종점이 된다. 이 기울기 자체가 이 표본의 발견이다.
- 실측값이 이미 있다 → 새 코딩 불필요.

### 1-8. 189 → 115 → 55 감쇄 깔때기
- **이유**: 이 서비스의 핵심 주장이 "줄어드는 것이 의도"인데 화면에 축소가 보이지 않는다.
  KPI 세 칸의 숨은 분모를 한 번에 공급한다.

### 1-9. 경쟁 비교표
AllSides / Ground News / 빅카인즈 / AgendaFrame × (무엇에 라벨 / 관측 단위 / 취재원 처리 / 검증 공개).
- **이유**: "다른 서비스와 무엇이 다릅니까"는 심사에서 100% 나온다. 표 하나가 가장 값싼 고득점 요소다.

### 1-10. 코드북 커버리지 정직 표시
`계열 39개 중 정의문 7개` + 미작성 계열은 "정의 미작성"으로 표시.
- 팝오버 각주를 **"이 정의는 사후 정리이며 코딩 프롬프트에 들어간 문서가 아니다"**로. 지금 실배포
  방법론 화면은 "두 코더가 서로 다른 순서로 라벨을 붙였다"까지만 말하고, 코더가 무엇을 봤는지는 말하지 않는다.

## 2. 흐름·정체성 (P1)

### 2-1. `/settings` 신설
시안 구성: 표시 방식(테마 3상태 · 글씨 크기 4단 · 애니메이션) / 나(표시 이름 · 읽기 유형) /
다른 기기(복구 코드 · 신원 초기화) / 읽기 기록 / 데이터(저장 목록 · 내려받기 · 삭제).
- **테마는 2상태 뒤집기가 아니라 3상태**여야 한다(시스템으로 되돌릴 방법이 없다).
- **글씨 크기는 실제로 작동해야 한다.** 시안에서 확인: px 고정을 em 으로 옮기지 않으면 컨트롤이
  거짓 약속이 된다(실측 본문 11.5→14.5px, 문서 높이 3814→4242px).
- **데이터 섹션은 선택이 아니다.** 익명 해시·자가점검 응답·글을 저장하면서 그 목록을 보여주는 화면이 없다.

### 2-2. 복구 코드 (1단계 신원)
계정·이메일 없이 12자 코드로 기기 간 이어짐. `actor_hash`가 이미 신원 축이므로
**"코드 → actor_hash" 매핑 테이블 하나**만 추가하면 된다.
- 이것으로 해결되는 것: 기기 간 이어짐 · "내 글" 식별(→ 수정·삭제 가능) · 표시 이름 소유.
- 소셜 로그인은 알림·팔로우가 생길 때. 그때는 개인정보 처리방침·동의·**탈퇴·삭제 엔드포인트**가 같이 필요하다
  (지금 보존/삭제 정책 코드가 0건).

### 2-3. 자가점검을 본체와 연결
시안: 한 문항씩 + 진행률 + 결과에서 **취약 층위를 도출해 그 층위 화면으로 딥링크**(BMOR → `#L5`).
- 실배포는 12문항이 한 화면에 다 나오고, 결과의 다음 행동이 커뮤니티 링크 하나다.
- 16유형 표는 결과를 본 뒤에 펼치게(지금은 미완성 시 정답표가 먼저 보인다).
- 결과 공유 수단이 없다 — 이 서비스에서 유일하게 퍼질 자산이다.

### 2-4. 막다른 화면 없애기
`/outlets`, `/report`, `/tools/method` 는 나가는 링크가 0개다. 시안의 `.next` 카드 3개를 넣는다.
리포트 각 단락 끝에 `→ 해당 층위 근거` 앵커 — "모든 문장은 근거에 연결됩니다"가 참이 되게.

### 2-5. 모바일 구조
- 사이드바 9항목 가로 스크롤 → **하단 탭 5개**(홈·의제·분석·내 습관·설정). 자가점검이 탭에 있어야 한다.
- 그룹 라벨과 기준일이 `display:none` 으로 사라지는 문제 → 기준일은 상단 배지로.
- 층위 레일은 모바일에서 sticky 해제(3행 192px 고정은 844px 화면에서 감당 불가).

## 3. 접근성 (시안에서 실제로 고친 것 = 실배포에도 있을 것)

| 항목 | 시안에서 확인한 증상 | 조치 |
|---|---|---|
| 점착 헤더 겹침 | 상단바가 배너에 45px 가려져 의제 선택이 포인터로 도달 불가 | `--bar` 를 ResizeObserver 로 실측 동기화, `scroll-padding-top` 도 같은 변수 |
| 다크 버튼 대비 | `.btn{color:#fff}` on 밝은 브랜드색 = 2.39:1 | `--n1-ink` 토큰 사용 (이미 있는데 안 쓰고 있었다) |
| 계열색 = 브랜드색 | 한 계열이 "정답", 다른 계열이 "경고"로 읽힘 | 데이터 계열색을 UI 크롬과 분리(`--fam-a`/`--fam-b`) |
| 미관측을 opacity 로 | 2.03:1, 그리고 "미관측은 약한 것이 아니다"라는 논증과 반대로 인코딩 | 점선 칩 |
| 헤딩 안의 버튼·칩 | 헤딩 접근명이 "1. 문제 정의 … 3:2 갈림 … AI가 두 번 채점?" | 메타를 헤딩 밖으로 |
| 라디오 그룹 | 화살표 키 없음, 다시 누르면 선택 해제 | 로빙 tabindex + 화살표 + 해제 금지 |
| 화면 전환 통지 | SPA 전환이 스크린리더에 전달 안 됨 | `role="status"` 리전 + `document.title` |

| 긴 영문 토큰 | 해시 규칙 문자열이 `keep-all` 에서 줄바꿈되지 않아 화면을 넓힘 | `code,pre{overflow-wrap:anywhere}` |

## 4. 데이터·파이프라인 (시안이 요구하는 것)

시안을 실데이터로 채우려면 아래가 선행되어야 한다.

1. **카파를 계산할 수 있게 저장 구조를 바꾼다.** 지금 `coder-agreement` 파일은 일치 여부(참/거짓)만
   담아 분류표를 만들 수 없다. **코더별 계열 라벨을 함께 저장**해야 κ·α 를 채울 수 있다.
   → 시안은 이 사실을 화면에 "산출 불가 — 데이터 구조가 허용하지 않음"으로 적어 두었다.
2. **매체명을 가린 재코딩**(25건). 비용이 낮고, 이 서비스의 전제를 지키는 유일한 증거다.
3. **코드북 v1** — 계열 39개 정의 + 경계 예시 2개씩. 다른 모든 검증의 전제.
4. **locator 변별력 관문**: paragraph 가 전 항목 동일하면 빌드 실패. 지금 189/189 = 1 이 통과한다.
5. **claim 고유성**: 완전 중복 18행을 빌드에서 접거나 거부.
6. **claude 세대 생성 스크립트 복원** — 없으면 재현 패키지가 성립하지 않는다.
7. **인용-서술 정합 지표**: 항목별 `voice_kind` × `frame_family` 가 이미 있으므로 새 코딩 없이 계산 가능.
   시안이 이 표를 이미 그려 두었다("문장을 쓰지 않고 프레임을 실은 경우").
8. **홈 집계 = 의제 표 집계** 계약 테스트 1개.

## 5. 시안에서 의도적으로 하지 않은 것

- **매체에 점수를 매기지 않는다.** 축은 의제마다 새로 만들고, 같은 매체가 의제에 따라 다른 쪽에 놓인다.
- **시계열을 그리지 않는다.** 하루치 표본에서는 추이가 성립하지 않는다.
- **7건에서 백분율을 쓰지 않는다.** `3:2`, `4곳 동일` 처럼 카운트로 쓴다.
- **군집이라고 부르지 않는다.** M&K 는 1,522건을 썼고 이 의제는 7건이다. "관측된 층위 조합"이라 적고,
  두 조합이 문제 정의와 완전히 겹친다는 사실(정보량 0)을 함께 밝힌다.
- **실명에 가상 내용을 붙이지 않는다.** 시안의 의제·매체는 익명(A일보·B일보…)이다.
