# Documentation

Project documents are grouped by purpose:

- `planning/`: product backlog, sprint backlog, WBS, and schedule documents
- `specs/`: feature specification, use cases, UML, and the initial-five public contract
- `architecture/`: the target Google Cloud runtime design — a plan, not the shipped system
- `research/`: prior research and prior service review
- `process/`: deliverable creation workflow
- `feedback/`: review notes written against the live site
- `submission/`: final report and local submission artifacts

Two single files sit at the top of this directory:

- `deploy.md`: how a commit reaches <https://agendaframe-capstone.vercel.app>
- `final-release-review.md`: the meaning-and-release checklist signed before launch

Documents describing the shipped system live next to it in `site/docs/`.
Large ZIP files and private forms should stay untracked.
